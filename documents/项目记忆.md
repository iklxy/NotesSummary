## 1. 项目整体目标

- 面向访谈音频的“端到端 Notes 系统”：
  - 本地音频 → 上云转写（ASR）→ 清洗 → 逐句 summary 落库
  - 基于题目（Question）的 RAG + LLM 生成 Notes（summary/analysis/evidence）
  - 支持 few‑shot 样本增强
  - 提供给前端一个可交互的 UI：项目 → 访谈 → QS & Notes → 详情页展示原文与 Notes。

当前进度：

- Python 引擎（SummaryNotes）端到端工作流已经打通。
- Python BFF（SummaryNotes-be）对外提供了 `/api/...` 接口，负责：
  - 项目管理
  - 访谈元信息 + 本地音频存储
  - 对外转发引擎内部的 workflow/notes 接口
- 前端（SummaryNotes-fe，Next.js + TS + AntD）已具备：
  - 项目列表
  - 新建项目
  - 新建访谈 + 上传音频
  - 访谈列表
  - 访谈详情页：左侧录音原文、右侧 QS & Notes。

## 3. 核心数据表（与当前代码直接相关）

### 3.1 `bh_project` —— 项目表

- 字段（只列当前用到的）：
  - `id`：项目 ID（PK，自增）
  - `name`：项目名称（唯一）
  - `keywords`：项目级关键词（可空）
  - `core_problem`：项目级核心问题描述（可空）

### 3.2 `bh_project_interview` —— 访谈主表

- 主要字段：
  - `id`：访谈 ID（PK，自增）
  - `parse_project_id`：项目 ID → `bh_project.id`
  - `name`：访谈名称
  - `keywords`：访谈关键词（当前代码未写入）
  - `core_problem`：该访谈核心问题总结（当前 BFF 不写）
  - `interview_date`：访谈时间（`datetime`，BFF 写入）
  - `file_id`：上游/COS 文件 ID（由 Workflow 写）
  - `file_path`：音频在 COS/TOS 上路径（Workflow 上传后写）
  - `file_name`：音频文件名（BFF 创建访谈时写）
  - `file_content`：ASR + 清洗后的 CSC JSON（Workflow 写）
  - `status`：处理状态（0待处理/1处理中/2完成/3失败）

### 3.3 `bh_project_interview_summary` —— 访谈明细表

- 用于左侧录音原文展示。
- 字段（与展示相关）：
  - `id`
  - `project_interview_id`
  - `timestamp`
  - `speaker`
  - `text`

### 3.4 `bh_project_question` —— 题目表

- 用于按题目维度生成 Notes。
- 字段（与当前代码使用相关）：
  - `id`
  - `project_interview_id`
  - `question_order`
  - `question_text`
  - `question_type`
  - `research_phase`
  - `intent_id`
  - `meta`

### 3.5 `bh_project_interview_notes` —— Notes 结果表

- 用于右侧 QS & Notes 展示。
- 字段（与展示相关）：
  - `id`
  - `project_id`
  - `project_interview_id`
  - `question_id`
  - `intent_id`
  - `note_json`：包含 `summary`、`analysis`、`evidence`、`confidence` 等。
  - `confidence`
  - `status`

## 4. 后端 API 一览（当前主要对外能力）

### 4.1 项目 API（summarynotes-be/api/projects.py）

- `POST /api/projects`
  - 功能：新建项目（插入 `bh_project`）。
  - 请求体（JSON）：
    - `name`（必填）
    - `keywords`（可空）
    - `core_problem`（可空）
  - 响应：`{ id, name, keywords, core_problem }`

- `GET /api/projects`
  - 功能：项目列表。
  - 响应：`[{ id, name, keywords, core_problem }, ...]`

### 4.2 访谈（项目维度）API（summarynotes-be/api/project_interviews.py）

- `POST /api/projects/{project_id}/interviews`（multipart/form-data）
  - 功能：
    - 在 `bh_project_interview` 插入一条访谈记录；
    - 将音频文件保存到 `audio/project_{project_id}/interview_{interview_id}/文件名`。
  - 路径参数：
    - `project_id`：项目 ID → `bh_project_interview.parse_project_id`
  - 表单字段：
    - `name`：访谈名称（必填）
    - `interview_date`：访谈时间（"YYYY-MM-DD"，可空）
    - `file`：音频文件（必选，单文件）
  - 响应：
    - `id`：访谈 ID
    - `project_id`
    - `name`
    - `interview_date`
    - `file_name`
    - `local_path`：相对路径 `project_{project_id}/interview_{interview_id}/{file_name}`

- `GET /api/projects/{project_id}/interviews`
  - 功能：查询某项目下所有访谈（从 `bh_project_interview`）。
  - 响应：
    - 数组，每项：
      - `id`
      - `parse_project_id`
      - `name`
      - `interview_date`
      - `file_name`

### 4.3 工作流与 Notes API（summarynotes-be/api/interviews.py）

- `POST /api/interviews/{interview_id}/run`
  - 功能：触发引擎 Workflow：上云 + ASR + 清洗 + summary/notes 落库。
  - 内部调用：`POST /internal/interviews/{interview_id}/run-workflow`
  - 响应：精简版 `RunInterviewResponse`，包含：
    - `success`
    - `summary_inserted`
    - `notes_inserted`
    - `message`

- `GET /api/interviews/{interview_id}/notes`
  - 功能：按题目聚合的 Notes 列表（联表题目 + notes）。
  - 内部调用：`GET /internal/interviews/{interview_id}/notes`
  - 响应结构（已定义于 `schemas/interviews.py`）：
    - `interview_id`
    - `project_id`
    - `questions: [ { question_id, question_order, question_text, question_type, intent_id, research_phase, notes: [ { notes_id, intent_id, note_json, confidence, status } ] } ]`

- `GET /api/interviews/{interview_id}/questions`
  - 功能：获取访谈题目列表（`bh_project_question`）。
  - 内部调用：`GET /internal/interviews/{interview_id}/questions`
  - 响应：`{ interview_id, questions: [ { id, project_interview_id, question_order, question_text, question_type, research_phase, intent_id } ] }`

- `GET /api/interviews/{interview_id}/summary`
  - 功能：拉取访谈原文明细（左侧“录音原文”）。
  - 直接从 `bh_project_interview_summary` 读：
    - `SELECT id, project_interview_id, timestamp, speaker, text FROM ... ORDER BY id ASC`
  - 响应：
    - `interview_id`
    - `items: [ { id, project_interview_id, timestamp, speaker, text } ]`

## 5. 前端功能现状

### 5.1 项目列表页（app/page.tsx）

- 加载逻辑：
  - 初始化时调用 `GET /api/projects`，填充 `projects` state。
  - 展开某个项目的“箭头”时：
    - 若该项目尚未加载访谈列表，则调用 `GET /api/projects/{project_id}/interviews`；
    - 将返回的访谈映射为前端 `interviews` 数组，展示于“访谈列表”。

- UI：
  - 顶部 Header：`SummaryNotes 项目列表`（深色背景，白色标题）。
  - 卡片：项目列表：
    - 项目名称
    - 关键词
    - 核心描述（core_problem）
    - 按钮：
      - `新建项目`（右上）
      - 每个项目行右侧：`新建访谈` + `编辑项目`
    - 左侧有一个向下箭头，控制“访谈列表”的展开/收起。

- “新建项目”：
  - 弹窗表单字段：
    - 项目名称（必填）
    - 项目关键词（可选）
    - 访谈核心描述（可选，对应 `core_problem`）
  - 提交：
    - 调用 `POST /api/projects`；
    - 成功后将返回项目追加到 `projects`。

- “新建访谈”：
  - 弹窗表单字段：
    - 所属项目（只读）
    - 访谈名称（必填）
    - 访谈时间（DatePicker，可选）
    - 录音文件上传（Upload，只选 1 个，限制 wav/mp3/m4a）
  - 提交：
    - 构造 `FormData`：`name` / `interview_date` / `file`；
    - 调用 `POST /api/projects/{project_id}/interviews`；
    - 成功后将返回的访谈追加到该项目的 `interviews` 列表中，并展开该项目。

- “访谈列表”：
  - 每条访谈显示：
    - 名称
    - 时间 + 文件名（小字）
  - 右侧按钮：
    - `详情`：跳转到 `/interviews/{interview_id}` 页面；
    - `删除`：当前仅本地删除（未调用后端删除 API）。

### 5.2 访谈详情页（app/interviews/[interviewId]）

- 路由拆分：
  - `page.tsx`：Server Component，仅负责从 `params.interviewId` 解析数字，并将 `safeId` 传给 Client 组件。
  - `client.tsx`：Client Component，负责实际 UI 和调用接口。

- client.tsx 行为：
  - 输入参数：`interviewId: number`（安全 ID，<=0 时视为无效）。
  - 左侧：
    - 调用 `GET /api/interviews/{id}/summary`；
    - 将 `bh_project_interview_summary` 的记录按聊天气泡方式展示：
      - 第一个出现的 speaker → 左侧气泡（白色）
      - 第二个出现的 speaker → 右侧气泡（浅蓝）
      - 显示 `speaker · timestamp` 和文本。
  - 右侧：
    - 调用 `GET /api/interviews/{id}/notes`；
    - 每个 question 一个卡片：
      - 标题：`question_order. question_text`
      - 内容：
        - 取 `notes[0].note_json.summary` 显示 Summary；
        - 取 `notes[0].note_json.analysis` 显示 Analysis；
        - 若两者都没有，则显示“该题暂无可展示的 Notes。”

## 6. 重要约定与注意事项

1. **职责边界**
   - SummaryNotes（引擎）：
     - 负责 Workflow（上云 + ASR + 清洗 + summary + RAG + Notes + few‑shot）。
     - 负责写入 `bh_project_interview_summary` 和 `bh_project_interview_notes` 等表。
   - summarynotes-be（BFF）：
     - 负责项目/访谈元信息增删改查（`bh_project`、`bh_project_interview` 等）。
     - 负责本地存储音频文件到 `audio/` 目录。
     - 对外统一 `/api/...`，内部再调引擎 `/internal/...`。

2. **音频目录**
   - BFF 固定写入 `SummaryNotes/audio/...`，不再读取 `LOCAL_AUDIO_ROOT`，这是给引擎的配置。
   - 引擎的 `build_local_file_path` 必须与 BFF 的路径规则保持一致。

3. **ID 一致性**
   - 前端所有访谈 ID 均以 `bh_project_interview.id` 为准，不再使用“本地 nextId”。
   - 路由 `/interviews/{interviewId}` 与 DB 记录一一对应。

4. **错误处理**
   - BFF 对引擎错误做了简单映射：
     - 404 → `interview not found` 或类似；
     - 5xx → `internal service failed`；
   - 前端在 API 封装中会抛 `Error`，页面层捕获后用 AntD `message` 或 `Alert` 显示。
