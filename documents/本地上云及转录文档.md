# 本地上云与转写结果存储规范

---

## 1. 本地上云接口返回 JSON

### 1.1 顶层返回结构

所有上传相关接口（如 `upload_local_file`、将来扩展的 `upload_interview_audio`）统一返回如下结构：

```json
{
  "success": true,
  "code": 0,
  "message": "upload success",
  "data": {}
}
```

字段说明：

- `success`：布尔  
  - `true`：本次调用整体成功  
  - `false`：本次调用整体失败
- `code`：整数  
  - `0`：成功  
  - 非 `0`：失败，对应错误码表
- `message`：字符串  
  - 面向人类的简短说明，便于日志和前端展示
- `data`：对象  
  - 成功时：承载业务数据（项目/访谈/URL 等）  
  - 失败时：承载与错误相关的上下文（如 `interview_id`、`local_file_path` 等）

### 1.2 成功返回示例

```json
{
  "success": true,
  "code": 0,
  "message": "upload success",
  "data": {
    "project_id": 101,
    "interview_id": 5001,
    "file_name": "raw_5001.wav",
    "object_key": "audio/project_101/interview_5001/raw_5001.wav",
    "bucket_name": "benhealth",
    "audio_url": "https://tos-cn-shanghai.volces.com/benhealth/audio/project_101/interview_5001/raw_5001.wav?X-Tos-Signature=xxx",
    "status": "uploaded",
    "uploaded_at": "2026-04-10T12:34:56Z",
    "elapsed_seconds": 0.532
  }
}
```

字段说明（`data` 内）：

- `project_id`：整数  
  - 该访谈所属项目 ID，对应 `bh_project.id`  
  - 通常来自 `bh_project_interview.parse_project_id`
- `interview_id`：整数  
  - 访谈 ID，对应 `bh_project_interview.id`
- `file_name`：字符串  
  - 使用的音频文件名  
  - 优先来自 `bh_project_interview.file_name`，若为空可用兜底规则（如 `"{interview_id}.wav"`）
- `object_key`：字符串  
  - 在 TOS 中的对象 key，例如 `audio/project_101/interview_5001/raw_5001.wav`  
  - 会写入 `bh_project_interview.file_path`
- `bucket_name`：字符串  
  - TOS 桶名，例如 `benhealth`
- `audio_url`：字符串  
  - 为 TOS 对象生成的预签名访问 URL，供 ASR 拉取音频  
  - 有效期由 `TOS_URL_EXPIRE_SECONDS` 控制
- `status`：字符串  
  - 当前访谈音频在上云流程中的状态  
  - 示例：`"uploaded"` 表示“已上传，待 ASR”
- `uploaded_at`：字符串（ISO 时间）  
  - 上传完成时间（服务器时间），例如 `"2026-04-10T12:34:56Z"`
- `elapsed_seconds`：数值  
  - 本次上传耗时（秒），用于监控和排查性能

## 2. 上云错误码与失败返回 JSON

### 2.1 错误码对照表

#### 参数/本地环境错误（1xxx）

- `1001` `INVALID_INTERVIEW_ID`  
  - `interview_id` 缺失或格式非法（无法转换成整数）
- `1002` `INTERVIEW_NOT_FOUND`  
  - 数据库中找不到 `bh_project_interview` 记录
- `1003` `INVALID_PROJECT_ID`  
  - 访谈记录存在，但 `parse_project_id` 为空或非法
- `1004` `LOCAL_FILE_NOT_FOUND`  
  - 根据规则生成 `local_file_path` 后，本地文件不存在
- `1005` `LOCAL_FILE_NOT_READABLE`  
  - 本地文件存在但不可读（权限问题、损坏等）

#### 配置/TOS 客户端错误（2xxx）

- `2001` `TOS_CREDENTIALS_MISSING`  
  - `TOS_ACCESS_KEY` 或 `TOS_SECRET_KEY` 未配置
- `2002` `TOS_CONFIG_INVALID`  
  - `TOS_ENDPOINT` / `TOS_REGION` 等基础配置非法
- `2003` `TOS_BUCKET_ACCESS_DENIED`  
  - `bucket_name` 配置不存在，或当前 AK/SK 对该桶无访问权限

#### 上传/URL 生成错误（3xxx）

- `3001` `TOS_UPLOAD_CLIENT_ERROR`  
  - 调用 TOS 上传时，出现客户端异常（网络问题、签名异常、本地资源问题等）
- `3002` `TOS_UPLOAD_SERVER_ERROR`  
  - 调用 TOS 上传时，TOS 服务端返回错误（5xx 或 TOS 业务错误码）
- `3003` `TOS_PRESIGNED_URL_ERROR`  
  - 预签名 URL 生成失败（参数非法或 SDK 内部错误）

#### 数据库操作错误（4xxx）

- `4001` `DB_CONNECTION_ERROR`  
  - 无法连接到 MySQL（网络、账号、密码、端口等问题）
- `4002` `DB_QUERY_INTERVIEW_ERROR`  
  - 读取访谈记录的 SQL 执行失败
- `4003` `DB_UPDATE_INTERVIEW_ERROR`  
  - 上传成功后，写回 `bh_project_interview` 的 `file_path` / `file_id` / `status` 等字段失败

#### 其他未知错误（5xxx）

- `5000` `INTERNAL_UNKNOWN_ERROR`  
  - 未在上述分类中覆盖的其他异常，统一归入“内部未知错误”

成功时约定：

- `code = 0`，`success = true`

### 2.2 失败返回 JSON 示例

#### 2.2.1 本地文件不存在（1004）

```json
{
  "success": false,
  "code": 1004,
  "message": "local audio file not found",
  "data": {
    "interview_id": 5001,
    "local_file_path": "/data/audio/project_101/interview_5001/raw_5001.wav"
  }
}
```

- `local_file_path`：代码生成的本地文件路径，用于排查路径规则是否正确

#### 2.2.2 TOS 上传失败（客户端异常，3001）

```json
{
  "success": false,
  "code": 3001,
  "message": "tos upload client error",
  "data": {
    "interview_id": 5001,
    "object_key": "audio/project_101/interview_5001/raw_5001.wav",
    "bucket_name": "benhealth",
    "tos_error_type": "TosClientError",
    "tos_error_message": "network timeout"
  }
}
```

- `tos_error_type`：异常类型标签（如 `TosClientError`）
- `tos_error_message`：客户端异常信息（网络超时等）

#### 2.2.3 TOS 上传失败（服务端异常，3002）

```json
{
  "success": false,
  "code": 3002,
  "message": "tos upload server error",
  "data": {
    "interview_id": 5001,
    "object_key": "audio/project_101/interview_5001/raw_5001.wav",
    "bucket_name": "benhealth",
    "tos_status_code": 500,
    "tos_error_code": "InternalError",
    "tos_error_message": "internal server error"
  }
}
```

- `tos_status_code`：TOS HTTP 状态码
- `tos_error_code`：TOS 业务错误码
- `tos_error_message`：TOS 返回的错误信息

#### 2.2.4 数据库更新失败（4003）

```json
{
  "success": false,
  "code": 4003,
  "message": "db update interview error",
  "data": {
    "interview_id": 5001,
    "object_key": "audio/project_101/interview_5001/raw_5001.wav",
    "audio_url": "https://tos-cn-shanghai.volces.com/...",
    "db_error_message": "Deadlock found when trying to get lock"
  }
}
```

- `db_error_message`：数据库返回的错误信息，用于排查 SQL/锁等问题

#### 2.2.5 未知错误（5000）

```json
{
  "success": false,
  "code": 5000,
  "message": "internal unknown error",
  "data": {
    "interview_id": 5001,
    "detail": "trace_id=abc123; please check server logs"
  }
}
```

- `detail`：附加调试信息（例如 trace_id），用于定位日志

## 3. ASR 提交与查询 JSON 格式

### 3.1 提交转写任务（/submit）

在 `VolcengineConversion.submit_task` 中，构造的请求体为：

```json
{
  "app": {
    "appid": "8536362168",
    "token": "hbcwYqK-x6Zp0nE1lizuPHAPPBt5B84j",
    "cluster": "volc_auc_common"
  },
  "user": {
    "uid": "388808087185088_demo"
  },
  "audio": {
    "format": "wav",
    "url": "https://tos-cn-shanghai.volces.com/benhealth/..."
  },
  "additions": {
    "with_speaker_info": "False"
  }
}
```

字段说明：

- `app.appid`：ASR 应用 appid，对应 `ASR_APP_KEY`
- `app.token`：ASR 应用 access key，对应 `ASR_ACCESS_KEY`
- `app.cluster`：ASR 集群名称，对应 `VOLCANO_CLUSTER`
- `user.uid`：用户 ID，可用于业务侧区分请求来源
- `audio.format`：音频格式（`wav` / `mp3` 等），与你上游编码保持一致
- `audio.url`：音频的预签名 URL，即上云后生成的 `audio_url`
- `additions.with_speaker_info`：是否返回说话人信息（字符串 `"True"` / `"False"`）

API 返回示例（成功时）：

```json
{
  "reqid": "xxxx-xxxx-xxxx",
  "resp": {
    "id": "asr_task_id_123",
    "code": 1000,
    "message": "ok"
  }
}
```

- `resp.id`：ASR 任务 ID，后续查询用
- `resp.code`：业务状态码，`1000` 通常表示受理成功

### 3.2 查询转写任务（/query）

查询请求体：

```json
{
  "appid": "8536362168",
  "token": "hbcwYqK-x6Zp0nE1lizuPHAPPBt5B84j",
  "id": "asr_task_id_123",
  "cluster": "volc_auc_common"
}
```

字段说明：

- `appid`：同上
- `token`：同上
- `id`：任务 ID，即提交时返回的 `resp.id`
- `cluster`：集群名称

查询返回示例（成功完成时）：

```json
{
  "reqid": "xxxx-xxxx-xxxx",
  "resp": {
    "code": 1000,
    "message": "success",
    "text": "这是整场识别后的文本……",
    "utterances": [
      {
        "text": "第一句……",
        "start_time": 0,
        "end_time": 5230,
        "speaker": "SPK1",
        "words": [
          { "text": "第", "start_time": 0, "end_time": 100 },
          { "text": "一句", "start_time": 100, "end_time": 300 }
        ]
      }
    ]
  }
}
```

字段说明（`resp` 内）：

- `code`：业务状态码  
  - `1000`：转写成功，可从 `text` / `utterances` 取结果  
  - 其他 `<2000`：失败，`message` 中有原因
- `message`：状态说明
- `text`：整场文本（可能为空）
- `utterances`：数组，每个元素表示一小段（可选字段）：
  - `text`：该段的完整文本
  - `start_time` / `end_time`：时间戳（单位视接口约定，一般为毫秒或帧）
  - `speaker`：说话人 ID（如 `"SPK1"`）
  - `words`：词级细节，包含每个词的文本和时间范围

在 `run_asr` 中：

- 优先使用 `resp.text`；
- 若为空，则遍历 `utterances`：
  - 有 `text` 就直接使用；
  - 没有 `text` 时，拼接 `words.text`；
- 最终将所有段落用换行拼接得到整场 `full_text`。

## 4. 转写结果写入 file_content 的 JSON

### 4.1 目标字段与类型

- 表：`bh_project_interview`
- 字段：`file_content`  
  - 类型建议：`longtext`  
  - 内容：整场转写结果的 JSON 快照

### 4.2 JSON 结构约定

```json
{
  "audio": {
    "project_id": 1,
    "interview_id": 1,
    "object_key": "audio/project_1/interview_1/1.wav",
    "bucket_name": "benhealth",
    "url": "https://tos-cn-shanghai.volces.com/benhealth/audio/project_1/interview_1/1.wav?X-Tos-Signature=xxx",
    "format": "wav"
  },
  "result": {
    "full_text": "这是整场访谈的转写文本，每一小段之间可以使用换行进行分隔……"
  }
}
```

字段说明：

- `audio.project_id`：项目 ID，对应 `bh_project.id`
- `audio.interview_id`：访谈 ID，对应 `bh_project_interview.id`
- `audio.object_key`：TOS 对象 key，形如 `audio/project_{project_id}/interview_{interview_id}/{file_name}`
- `audio.bucket_name`：TOS 桶名
- `audio.url`：本次 ASR 使用的预签名 URL
- `audio.format`：音频格式，由文件名自动推导（扩展名小写，不含点）  
  - 规则示例：
    - `"1.wav"` → `"wav"`
    - `"demo.MP3"` → `"mp3"`
    - 无扩展名 → 默认 `"wav"`

- `result.full_text`：整场转写文本  
  - 可将每条 `utterance` 或按逻辑分段的文本用换行符连接形成一个长文本  
  - 后续如需按句子拆分，可在独立任务中解析该字段

### 4.3 写库流程概述

以 `interview_id` 为入口，写入 `file_content` 的步骤为：

1. 使用 `get_interview_by_id(interview_id)` 获取访谈记录；
2. 确定 `project_id` / `file_name` / `object_key`；
3. 使用 TOS 预签名接口生成 `audio_url`；
4. 使用 `run_asr(audio_url)` 调用 ASR，得到 `full_text` 字符串；
5. 构造上述 JSON 结构并 `json.dumps` 成字符串；
6. 调用 `update_interview_file_content(interview_id, file_content_json)` 更新 `bh_project_interview.file_content`。
