你现在是一个前后端交互设计师。前端交互的基本交互逻辑有 
（1）点击新建项目，用户能够上传项目的名称，关键词（参考数据库bh_project表）
详细需求描述：
-插入bh_project表，主键id自增，name项目名称，keywords项目关键词

（2）在创建了新项目之后，用户可以在新项目的目录层级下新建访谈，可上传访谈的名称，关键词，访谈需要总结的问题等（参考bh_project_interview,bh_project_question)，以及本地音频文件（用于上云）
详细需求：
-插入bh_project_interview表，主键id自增，project_id项目id，name访谈名称
-本地音频文件上传后需先存到该项目服务的audio目录下，根据项目名和访谈名创建对应的文件夹，然后上云，数据库的写入逻辑在Workflow.py中

（3）之后前端页面显示loading（或者loading动画），等待上云完成。上云完成之后，提示用户访谈已成功上传，然后再次loading等待服务处理完成。完成之后用户可点击访谈查看访谈明细表的内容（具体见bh_project_interview表）

(4)除了可以看见访谈明细以外，还可以看见针对每一额question的notes_result（具体见bh_project_question表以及bh_project_interview_question表）

## 一、整体架构与分层

- 前端（TypeScript + React/Next 等）
- Go 主服务（对外 API 层，提供 `/api/...`）
- Python 子服务（Notes Engine，提供 `/internal/...`）
- MySQL + Qdrant + 本地 audio 目录

调用链：前端 → Go `/api/...` → Python `/internal/...` → 数据库/向量库 → Go → 前端。

---

## 二、业务流程拆解与接口设计

### 2.1 新建项目（对应（1））

**前端交互**

- 项目列表页点击「新建项目」，填写项目名称、关键词。

**HTTP 接口（Go → 前端）**

- `POST /api/projects`
  - 请求：
    ```json
    {
      "name": "CI Dako 项目",
      "keywords": "CI, Dako, 不良反应"
    }
    ```
  - 响应：
    ```json
    {
      "id": 1,
      "name": "CI Dako 项目",
      "keywords": "CI, Dako, 不良反应",
      "created_time": "2026-02-04T10:00:00",
      "last_updated_time": "2026-02-04T10:00:00"
    }
    ```

**数据落库**

- 插入 `bh_project`：
  - `id` 自增
  - `name`、`keywords` 来自前端。

（可选）项目列表：

- `GET /api/projects?status=active&page=1&page_size=15`
  - 直接查询 `bh_project`，用于项目列表页。

---

### 2.2 新建访谈 + 音频上传（对应（2））

拆成两步：  
1）创建访谈元信息 + 题目配置  
2）上传本地音频文件到 audio 目录

#### 2.2.1 新建访谈元信息

**前端交互**

- 在某项目卡片内点击「新建访谈」，填写名称、关键词，并配置题目列表。

**接口：**

- `POST /api/projects/{project_id}/interviews`
  - 请求：
    ```json
    {
      "name": "CI Dako 专家访谈01",
      "keywords": "肺癌, Dako, IHC",
      "questions": [
        {
          "question_order": 1,
          "question_text": "根据访谈内容，艾德生物2025年国内整体营收规模大约是多少？",
          "question_type": "OPEN",
          "intent_id": 1
        }
      ]
    }
    ```
  - 响应：
    ```json
    {
      "interview_id": 1,
      "project_id": 1,
      "name": "CI Dako 专家访谈01"
    }
    ```

**数据落库**

- 插入 `bh_project_interview`：
  - `id` 自增
  - `parse_project_id` 或 `project_id` = 路径里的 `{project_id}`
  - `name`、`keywords` 来自请求。
- 批量插入 `bh_project_question`：
  - `project_interview_id` = 新访谈 id
  - `question_order`、`question_text`、`question_type`、`intent_id`。

#### 2.2.2 上传本地音频文件（保存到 audio 目录）

**前端交互**

- 访谈详情页点击「上传音频」，选择本地文件并提交。

**接口：**

- `POST /api/projects/{project_id}/interviews/{interview_id}/audio`
  - 请求：`multipart/form-data`，字段名 `file`。
  - 后端逻辑：
    - 将文件保存到本地：
      - 根目录：`audio/`
      - 路径规则：`audio/project_{project_id}/interview_{interview_id}/{原文件名}`
      - 与 `VolcUpload.build_local_file_path` 保持一致。
  - 响应：
    ```json
    {
      "success": true,
      "local_path": "audio/project_1/interview_1/xxx.mp3"
    }
    ```

后续 Go 会调用 Python 子服务执行完整 Workflow（见下一节）。

---

### 2.3 Workflow 执行与 loading（对应（3））

**前端交互**

- 用户点击「开始处理」按钮（或上传后自动触发）：
  - 前端调用：`POST /api/interviews/{interview_id}/run`
  - 显示处理中的 loading 状态。

**Go → Python 子服务**

- Go 接口：
  - `POST /api/interviews/{interview_id}/run`
    - 内部调用 Python：
      - `POST /internal/interviews/{interview_id}/run-workflow`
    - Python 使用当前的 `Workflow.run_workflow(interview_id)` 执行步骤：
      - 本地上云 → ASR → 清洗 → 写 summary → 生成 Notes → 写入 `bh_project_interview_notes`。

**Python 返回结果示例**

```json
{
  "success": true,
  "object_key": "audio/project_1/interview_1/xxx.mp3",
  "audio_url": "https://tos.xxx/...",
  "asr_result_preview": {
    "full_text_len": 12345,
    "speakers_count": 2
  },
  "summary_inserted": 143,
  "notes": {
    "success": true,
    "total_questions": 5,
    "results": [...]
  },
  "notes_db": {
    "success": true,
    "inserted": 5,
    "errors": []
  }
}
```

Go 可以简化后返回前端：

```json
{
  "success": true,
  "summary_inserted": 143,
  "notes_inserted": 5
}
```

**前端 loading 逻辑**

- 调用 `/api/interviews/{id}/run` 时：
  - 显示 “正在上云并转写，请稍候...” 的 loading 动画。
- 返回成功后：
  - 弹出“访谈处理完成”提示；
  - 自动刷新访谈明细页（调用 `/api/interviews/{id}/notes`）。

### 2.4 查看访谈明细与 Notes（对应（4））

**接口 1：访谈明细**

- `GET /api/interviews/{interview_id}`
  - 返回 `bh_project_interview` 信息：
    ```json
    {
      "id": 1,
      "project_id": 1,
      "name": "CI Dako 专家访谈01",
      "keywords": "肺癌, Dako, IHC",
      "interview_date": "2026-02-03",
      "status": 2
    }
    ```

**接口 2：按题目查看 Notes**

- `GET /api/interviews/{interview_id}/notes`
  - 需要联表 `bh_project_question` + `bh_project_interview_notes`：
    - 每个题目包含对应的 Notes 列表。
  - 响应示例：
    ```json
    {
      "interview_id": 1,
      "project_id": 1,
      "questions": [
        {
          "question_id": 1,
          "question_order": 1,
          "question_text": "根据访谈内容，艾德生物2025年国内整体营收规模大约是多少？",
          "question_type": "OPEN",
          "intent_id": 1,
          "notes": [
            {
              "notes_id": 10,
              "intent_id": 1,
              "note_json": {
                "summary": "...",
                "analysis": "...",
                "evidence": [...],
                "confidence": 0.92
              },
              "status": 0
            }
          ]
        }
      ]
    }
    ```

**前端展示**

- 项目列表页：显示项目名称、创建/更新时间、下拉显示该项目下的访谈列表（类似截图）。
- 访谈详情页：
  - 上方显示访谈基本信息（日期、创建人、状态等）。
  - 中间按题目展示 Notes 卡片：
    - 标题：`question_order + question_text`
    - 内容：`summary` + `analysis`
    - 可展开 evidence 查看引用原文。

  - `POST /api/notes/{notes_id}/review`

  - 定期扫描 `bh_project_interview_notes` 及编辑日志，将高质量 Notes 写入 `bh_project_fewshot_sample` 作为 few-shot 样本。

  - 将 `/api/interviews/{id}/run` 改为异步任务，返回 `task_id`；
  - 前端轮询 `GET /api/tasks/{task_id}` 获取进度，支持更细粒度的 loading 与错误提示。
