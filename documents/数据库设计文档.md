# Notes 功能数据库设计说明

---


### 0.1 `bh_project` —— 项目表

**功能**：存放解析项目/研究项目的基本信息，是 Notes 系统中所有“项目级配置”的根实体。

**主要字段**

| 字段名            | 类型         | 含义                         | 约束                 |
|-------------------|--------------|------------------------------|----------------------|
| `id`              | bigint PK    | 项目 ID                      | 主键，自增或外部导入 |
| `name`            | varchar(255) | 项目名称                     | 唯一（UNI）          |
| `keywords`        | text         | 项目级关键词                 | 可空                 |
| `core_problem`    | text         | 项目级核心问题描述           | 可空                 |

**与 Notes 的关系**

- 下游多表通过 `project_id` 外键关联本表。
- 现有 `bh_project_interview.parse_project_id` 与本表 `id` 对应，一场访谈属于一个项目。

---

### 0.2 `bh_project_interview` —— 访谈主表

**功能**：记录每一场访谈的元信息、文件信息及整场处理结果。

**主要字段（与 Notes 相关部分）**

| 字段名           | 类型        | 含义                                   | 约束                                |
|------------------|-------------|----------------------------------------|-------------------------------------|
| `id`             | bigint PK   | 访谈 ID                                | 主键                                |
| `parse_project_id` | bigint    | 项目 ID，指向 `bh_project.id`         | 外键逻辑关联（当前 DB 未显式约束） |
| `name`           | varchar(255)| 访谈名称                               | 可空                                |
| `keywords`       | text        | 访谈关键词                             | 可空                                |
| `core_problem`   | text        | 本访谈的核心问题总结                   | 可空                                |
| `interview_date` | datetime    | 访谈时间                               | 可空                                |
| `file_id`        | varchar(100)| 上游或 COS 中的文件 ID                 | 可空                                |
| `file_path`      | text        | 音频在 COS 中的路径                    | v2t 依赖此字段                      |
| `file_name`      | text        | 音频文件名                             | 可空                                |
| `file_content`   | longtext    | 整场访谈 CSC JSON 文本                 | v2t 写入                            |
| `note_content`   | longtext    | **整场级 Notes 文本（预留）**          | Notes 可复用                        |
| `status`         | tinyint(3)  | 处理状态：0待处理/1处理中/2完成/3失败 | 可空                                |
| `problem_answer` | json        | 结构化问答（问题→答案）                | 可空                                |

**与 Notes 的关系**

- Notes 结果表通过 `project_interview_id` 外键指向本表。
- few‑shot 样本可以记录“来源访谈”。

---

### 0.3 `bh_project_interview_summary` —— 访谈明细表

**功能**：存储逐句发言，带时间戳和说话人，是 Notes 提取的核心上下文数据。

**主要字段**

| 字段名               | 类型        | 含义                                 | 约束                                |
|----------------------|-------------|--------------------------------------|-------------------------------------|
| `id`                 | bigint PK   | 明细行 ID                            | 主键，自增                          |
| `project_interview_id` | bigint    | 所属访谈 ID → `bh_project_interview.id` | 外键逻辑关联                        |
| `timestamp`          | varchar(20) | 时间戳或时间范围                     | 可空                                |
| `speaker`            | varchar(255)| 说话人角色/ID（如“专家”“访者”）     | 可空                                |
| `text`               | longtext    | 纠错 & 清洗后的发言内容             | 可空                                |
| `modify`             | tinyint(2)  | 是否被人工修改过（0/1 或枚举）       | 默认 0                              |

**与 Notes 的关系**

- Notes 模块按题目切片时，会从该表读取原文和时间戳。
- Notes evidence 中的“原文片段”可通过 `timestamp + speaker` 回溯到这里。

## 1. 必须新增的 Notes 相关表

### 1.1 `bh_question_intent` —— 意图定义表

**功能**：定义 Notes 的“模块类型”，例如“疗效体验、不良反应、典型病例、GUIDELINE 引用、Quotes 精选”等。  
所有题目和 Notes 结果都通过 `intent_id` 引用此表，形成统一的模块体系。

**字段设计**

| 字段名      | 类型          | 含义                                     | 约束                          |
|-------------|---------------|------------------------------------------|-------------------------------|
| `id`        | bigint PK     | 意图 ID                                  | 主键                          |
| `code`      | varchar(100)  | 意图编码，如 `SAFETY_EXPERIENCE`        | 唯一，索引用于代码逻辑       |
| `name`      | varchar(255)  | 意图名称，如“不良反应体验”             | 可空                          |
| `description` | text        | 描述用途与边界                          | 可空                          |
| `schema_name` | varchar(100)| Notes JSON Schema 名，例如 `notes_safety_schema` | 可空                |
| `status`    | tinyint       | 1=启用，0=停用                          | 默认 1                        |
| `created_time` | datetime   | 创建时间                                 | 可空                          |
| `last_updated_time` | datetime | 最后更新时间                         | 可空                          |

**约束与使用规范**

- `code` 必须唯一，作为业务代码中的常量。
- `schema_name` 与应用侧的 Schema 校验逻辑一一对应，修改前需评估兼容性。

---

### 1.2 `bh_project_question` —— 项目题目表

**功能**：存储每个访谈的问卷题目，是“按题目维度生成 Notes”的基础配置。

**字段设计**

| 字段名          | 类型         | 含义                                                     | 约束                                               |
|-----------------|--------------|----------------------------------------------------------|----------------------------------------------------|
| `id`            | bigint PK    | 题目 ID                                                  | 主键                                               |
| `project_interview_id`    | bigint       | 所属访谈 ID → `bh_project_interview.id`                            | 外键逻辑关联，必填                                 |
| `question_order`| int          | 问卷顺序（1,2,3…）                                      | 项目内建议唯一（`project_id + question_order` 唯一） |
| `question_text` | text         | 题目原文                                                 | 必填                                               |
| `question_type` | varchar(50)  | 题型/功能标签：（如 `OPEN`, `SAFETY_EXPERIENCE` 等）    | 必填，建议枚举                                    |
| `research_phase`| varchar(50)  | 研究阶段：`baseline` / `on_treatment` / `post_treatment` 等 | 可空，根据项目实际使用                             |
| `intent_id`     | bigint       | 主意图 → `bh_question_intent.id`                        | 可空；某些题可不绑定固定 intent                    |
| `meta`          | json         | 其他元数据（模块、标签、展示配置等）                     | 可空                                               |
| `created_by`    | bigint       | 创建人 ID                                                | 可空                                               |
| `created_time`  | datetime     | 创建时间                                                 | 可空                                               |
| `last_updated_by` | bigint     | 最后修改人 ID                                            | 可空                                               |
| `last_updated_time` | datetime | 最后修改时间                                             | 可空                                               |

**约束与关系**

- `project_id` 必须能在 `bh_project` 中找到对应记录。
- 在一个项目内，`question_order` 应该连续且唯一，方便 UI 展示和切分逻辑。
- `intent_id` 与题目在 Notes 中的主模块对应（如“这一题主要产生 ADR Notes”）。

---

### 1.3 `bh_project_interview_notes` —— Notes 结果表

**功能**：存储模型/人工生成的 Notes 结果，一条记录 = 某项目、某访谈、某题目、某意图下的一份 Notes。

**字段设计**

| 字段名              | 类型          | 含义                                                         | 约束                                  |
|---------------------|---------------|--------------------------------------------------------------|---------------------------------------|
| `id`                | bigint PK     | Notes 记录 ID                                                | 主键                                  |
| `project_id`        | bigint        | 项目 ID → `bh_project.id`                                    | 必填                                  |
| `project_interview_id` | bigint     | 访谈 ID → `bh_project_interview.id`                          | 必填                                  |
| `question_id`       | bigint        | 题目 ID → `bh_project_question.id`                           | 可空：整场级 Notes 时可以为空        |
| `intent_id`         | bigint        | 意图 ID → `bh_question_intent.id`                            | 必填                                  |
| `note_json`         | json          | 结构化 Notes 内容，遵循对应 `intent.schema_name`            | 必填                                  |
| `confidence`        | decimal(5,4)  | 模型自评置信度（0–1）                                       | 可空                                  |
| `status`            | tinyint       | Notes 状态：0自动生成/1已通过/2已编辑/3已拒绝/4错误         | 默认 0                                |
| `error_message`     | varchar(500)  | 生成或解析失败信息                                          | `status=4` 时可填                     |
| `created_by`        | bigint        | 生成者 ID（系统或任务）                                     | 可空                                  |
| `created_time`      | datetime      | 创建时间                                                     | 默认当前时间                          |
| `last_updated_by`   | bigint        | 最后更新人 ID                                               | 可空                                  |
| `last_updated_time` | datetime      | 最后更新时间                                                 | 可空                                  |

**约束与关系**

- `(project_id, project_interview_id, question_id, intent_id)` 可以加唯一索引，避免重复生成同一颗 Notes（视业务需求而定）。
- `project_id` 应与 `bh_project_interview.parse_project_id` 一致（由业务层控制）。
- `question_id` 允许为 NULL，用于“整场级 Notes”场景；题目级 Notes 必须非空。

---

### 1.4 `bh_project_notes_edit_log` —— Notes 编辑日志表

**功能**：记录每一次人工对 Notes 的操作（审批、修改、驳回），为审计和自学习提供数据。

**字段设计**

| 字段名          | 类型      | 含义                                          | 约束                           |
|-----------------|-----------|-----------------------------------------------|--------------------------------|
| `id`            | bigint PK | 日志记录 ID                                   | 主键                           |
| `notes_result_id` | bigint  | 对应的 Notes 记录 → `bh_project_nterview_notes.id` | 必填                           |
| `editor_id`     | bigint    | 编辑人 ID                                     | 必填                           |
| `action`        | varchar(50)| 操作类型：`approve` / `edit` / `reject` / `rewrite` | 必填，建议枚举              |
| `before_json`   | json      | 操作前 Notes 内容                             | 可空（首次 approve 可为空）   |
| `after_json`    | json      | 操作后 Notes 内容                             | 必填                           |
| `quality_score` | tinyint   | 编辑人给本条 Notes 打分（0–100）             | 可空                           |
| `comment`       | text      | 备注说明                                      | 可空                           |
| `created_time`  | datetime  | 操作时间                                      | 默认当前时间                   |

**约束与关系**

- `notes_result_id` 必须存在于 `bh_project_nterview_notes`。
- 一条 Notes 可以对应多条编辑日志，按时间记录整个生命周期。

---

### 1.5 `bh_project_fewshot_sample` —— few‑shot 样本表

**功能**：存储用于 Prompt few‑shot 注入的高质量示例，作为全局独立样本池，支持按项目/题目/意图筛选。

**字段设计**

| 字段名               | 类型        | 含义                                                        | 约束                                      |
|----------------------|-------------|-------------------------------------------------------------|-------------------------------------------|
| `id`                 | bigint PK   | few‑shot 样本 ID                                            | 主键                                      |
| `project_id`         | bigint      | 项目 ID                                                     | 必填                                      |
| `project_interview_id` | bigint    | 来源访谈 ID                                                 | 可空（种子样本可为空）                   |
| `question_id`        | bigint      | 来源题目 ID                                                 | 必填                                      |
| `intent_id`          | bigint      | 意图 ID                                                     | 必填                                      |
| `notes_result_id`    | bigint      | 来源 Notes 记录 ID                                          | 可空：人工录入种子样本时可以不依赖现有记录 |
| `sample_json`        | json        | 提供给 LLM 的示例内容（结构与 `note_json` 一致即可）       | 必填                                      |
| `quality_score`      | tinyint     | 样本质量评分（0–100），≥80 认为可用                         | 必填                                      |
| `source_kind`        | varchar(20) | 样本来源：`seed` / `human_approved` / `auto_candidate`     | 必填，建议枚举                            |
| `created_time`       | datetime    | 创建时间                                                    | 默认当前时间                             |

**约束与关系**

- 常用查询组合：  
  `(project_id, question_id, intent_id, quality_score >= 80)` 按时间倒序，取最近 1–2 条。
- 可设置逻辑规则：对每个 `project_id + question_id + intent_id` 保持最多 N 条样本（由后台任务控制）。

## 2. 可选表（自学习与统计）

### 2.1 `bh_project_notes_stats_daily` —— Notes 每日统计表（可选）

**功能**：对 `bh_project_nterview_notes` 与 `bh_project_notes_edit_log` 进行每日离线统计，用于监控质量和发现需要优化的意图/题目。

**字段设计**

| 字段名          | 类型        | 含义                                                   | 约束                           |
|-----------------|-------------|--------------------------------------------------------|--------------------------------|
| `id`            | bigint PK   | 统计记录 ID                                           | 主键                           |
| `stat_date`     | date        | 统计日期                                             | 必填                           |
| `project_id`    | bigint      | 项目 ID → `bh_project.id`                             | 必填                           |
| `question_id`   | bigint      | 题目 ID → `bh_project_question.id`                    | 可空：整场级 Notes 统计可为 NULL |
| `intent_id`     | bigint      | 意图 ID → `bh_question_intent.id`                     | 可空：总体统计可为 NULL       |
| `total_count`   | int         | 当日生成的 Notes 条数                                | 默认 0                         |
| `edited_count`  | int         | 被编辑的 Notes 条数（`action in ('edit','rewrite')`）| 默认 0                         |
| `rejected_count`| int         | 被拒绝的 Notes 条数（`action = 'reject'`）           | 默认 0                         |
| `avg_quality_score` | decimal(5,2) | 平均质量评分（仅统计有评分的条目）           | 默认 0                         |
| `created_time`  | datetime    | 统计写入时间                                         | 默认当前时间                   |

**约束与关系**

- 通常对 `(stat_date, project_id, question_id, intent_id)` 加唯一索引，保证每天一行。
- 由离线任务（脚本或定时任务）每日汇总并写入。

## 3. 表之间的整体关系小结（文字版）

- `bh_project`（项目）
  - 1 — N `bh_project_interview`（访谈）
  - 1 — N `bh_project_question`（题目）
  - 1 — N `bh_project_nterview_notes`（Notes 结果）
  - 1 — N `bh_project_fewshot_sample`（few‑shot 样本）
  - （可选）1 — N `bh_project_notes_stats_daily`（Notes 统计）

- `bh_project_interview`（访谈）
  - 1 — N `bh_project_interview_summary`（逐句明细）
  - 1 — N `bh_project_nterview_notes`（与该访谈相关的所有 Notes）
  - 1 — N `bh_project_fewshot_sample`（来源于该访谈的 few‑shot）

- `bh_project_question`（题目）
  - N — 1 `bh_project`（归属项目）
  - N — 1 `bh_question_intent`（题目主意图）
  - 1 — N `bh_project_nterview_notes`（该题下的各意图 Notes）
  - 1 — N `bh_project_fewshot_sample`（该题的 few‑shot 样本）
  - （可选）1 — N `bh_project_notes_stats_daily`（该题统计）

- `bh_question_intent`（意图）
  - 1 — N `bh_project_question`
  - 1 — N `bh_project_nterview_notes`
  - 1 — N `bh_project_fewshot_sample`
  - （可选）1 — N `bh_project_notes_stats_daily`

- `bh_project_nterview_notes`（Notes 结果）
  - N — 1 `bh_project`
  - N — 1 `bh_project_interview`
  - N — 1 `bh_project_question`（题目级 Notes）或 NULL（整场级）
  - N — 1 `bh_question_intent`（题目主意图）
  - 1 — N `bh_project_notes_edit_log`
  - 1 — N `bh_project_fewshot_sample`（某些样本引用它）

- `bh_project_notes_edit_log`（编辑日志）
  - N — 1 `bh_project_nterview_notes`

- `bh_project_fewshot_sample`（few‑shot 样本）
  - N — 1 `bh_project`
  - N — 1 `bh_project_interview`（可空）
  - N — 1 `bh_project_question`
  - N — 1 `bh_question_intent`
  - N — 1 `bh_project_nterview_notes`（可空）

- `bh_project_notes_stats_daily`（可选统计）
  - N — 1 `bh_project`
  - N — 1 `bh_project_question`（可空）
  - N — 1 `bh_question_intent`（可空）

---

这份设计保证了：

- **必须有的能力**：项目/题目配置、按题目按意图存 Notes、人工审核与编辑记录、few‑shot 样本管理；
- **可选能力**：按日统计与质量监控，可以在系统稳定后再逐步补充。
